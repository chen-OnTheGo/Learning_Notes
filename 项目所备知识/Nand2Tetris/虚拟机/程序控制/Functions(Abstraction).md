
在本单元中，我们将从函数的抽象开始讨论函数这个概念，也就是说，如果你是一个VM程序员（虚拟机程序员），你将如何在代码中使用函数？

众所周知，可以使用子例程（Subroutines）、函数（Functions）、过程（Procedures）、方法(Methods)等来扩展高级函数。

函数就像一个黑匣子。你给它一些参数，按下按钮（运行），函数就会do something然后给出结果。不同的语言用不同的名称来调用这些函数。

这里的`Math.multiply` 是一个`Math`类中的函数，用于计算两个数的乘积。上面例子中的`multiply`将对 `x` 和 `5` 进行操作，并将`x * 5`的结果取代 `x` 和 `5`。
以此类推，`Math.sqrt`是`Math`类中的`sqrt`函数，用于计算某个值的平方根。

这里有两个有趣的现象。
第一个现象是，VM language有两种类型的运算：
- **primitive operations(fixed)**：`add`, `sub`, ... 这种运算是VM语言的一部分，并且其数量类别是有限的。若想使用其他运算，就需要使用封装好的函数（别人写的库或者自己编写函数），也就是第二种类型的运算
- **abstract operations(extensible)**：`multiply`, `sqrt`, ... 这种是程序员扩展的函数，可以自由创建和使用任意数量的函数。

第二个现象是
```
Applying a primitive operator and calling a funtion have the same look-and-feel.
```
这两种情况的规则都是，当我们要调用一个函数，并且这个函数需要三个参数时，并不是把参数交给函数然后等结果，而是先把这三个参数依次压入stack中，接着调用函数，函数会直接从stack顶部把这三个参数取走来计算。计算完成后，原来那三个参数在stack中消失了，取而代之的是一个新的值，也就是函数的返回结果。

需要注意的是，main的抽象视图和实际发生的事情是有区别的，比如，当我在main函数里面调用某个函数时，如何知道下一步是运行哪行代码？当调用完这个函数时，如何知道该接着运行main函数中的哪一步？
从现实的角度看，我们必须做些什么才能让这个“魔法”在这里发挥作用？

![](../../../../img/Pasted%20image%2020260223213803.png)

在程序运行的时候，每一次函数调用，其底层实现必须要做的事情：
- **传参**。将参数从`caller`传给`callee`。
- **确定返回地址**。（`callee`执行完，要回到`caller`的哪一行）
- **保存`caller`的当前状态**。其状态包括：`caller`的work stack, memory segments, return address.（这样当我们返回调用者的代码时，我们就能重新创建`main`的私有世界并像什么也没发生一样继续执行。或者说，函数调用就像暂时冻结`caller`的世界，进入另一个世界完成任务，回来时把冻结解除，一切恢复原状。）
- **跳转去执行**`callee`。

![](../../../../img/Pasted%20image%2020260223215610.png)

当执行`return`指令时，其底层实现必须要做的事情：
- 将`callee`的计算结果返回给`caller`。（这里有个隐含的假设就是：每个`callee`必须在执行`return`语句前`push`一个值到`stack`）
- 回收`callee`使用的内存段和内存资源。（因为`callee`现在已经无关紧要）
- 恢复或重新创建`caller`的`stack`和内存段。
- 程序计数器跳回到`caller`的下一条指令。

以上就是实现的要点。
